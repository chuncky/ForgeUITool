## 2. 产品愿景与定位

### 2.1 愿景

让基于 **qm10x 平台** 的带屏产品，能在 PC 上通过拖拽完成界面设计，一键得到可编译的 LVGL C 代码，并在本机与板端快速验证，从而把 UI 开发从「库 API 苦力」变成「可视设计 + 业务代码」分工。

### 2.2 一句话定位

> 面向 **qm10xd、qm10xv、qm10xh** 的 LVGL 可视化设计工具：自有 JSON 工程 → 拖拽设计 → **生成标准 LVGL C** → PC 真 LVGL 可点选 → **接入对应平台 SDK**；可选 **UI 包** 支持界面（及受限逻辑）动态更新。

### 2.3 产品属性

| 属性 | 定义 |
|------|------|
| 品类 | PC 端嵌入式 UI 设计器（范式 A：LVGL 源码导出） |
| 平台策略 | **平台绑定**（qm10x\*），非厂商中立通用工具 |
| 交付形态 | 桌面应用 + CLI；配套 SDK 模板与文档 |
| 图形栈 | 开源 LVGL + 平台 port；自研薄 Loader（A2，**默认启用**） |
| 工程格式 | 自有明文 JSON（许可与演进自控） |

### 2.4 定位坐标（相对竞品）

```text
                    厂商中立 / 订阅生态
                           ▲
                           │  SquareLine · LVGL Pro
                           │
    厚宿主应用包 ──────────┼────────── LVGL 源码导出
    Persim / FlyThings     │
                           │  ★ 本产品（qm10x 绑定 + 自有格式）
                           │  Beken / UIBuilder（他厂芯片）
                           │  EEZ（开源/GPL，偏通用+仪器）
                           ▼
                    芯片/方案绑定工具链
```

**本产品选择右下象限：** 与 SDK 强协同，用「最短上板路径 + 许可自控」赢，而不是用「控件数量 / 全球教程量」硬刚 SquareLine。

## 3. 目标用户与场景

### 3.1 目标用户

| 角色 | 描述 | 核心诉求 | 成功体验 |
|------|------|----------|----------|
| UI / 界面工程师 | 负责布局、切页、视觉资源 | 少写 LVGL 布局代码 | 拖拽出双页 demo，PC 可点 |
| 应用固件工程师 | 写业务、驱动、协议 | 生成不覆盖手写业务 | `custom/` 稳定，反复生成安心 |
| 方案 / FAE | 做评估板 demo、客户导入 | 模板 + 短文档上板 | 半天级跑通首屏 |
| 量产维护（V1+） | 改皮肤/改文案布局 | 尽量不重编业务固件 | 换 UI 包即可（A2） |

### 3.2 非目标用户（本阶段）

- 需要完整「应用商店 / 多 App 宿主」的智能屏操作系统客户 → 另立范式 B  
- 需要 SCPI/仪器测控 IDE 的用户 → 非本产品  
- 要求打开并兼容 SquareLine/Pro 工程的迁移用户 → 不做 L4 兼容（可手工重做） |

### 3.3 关键使用场景

| ID | 场景 | 价值 |
|----|------|------|
| S1 | 新项目：选 qm10x 平台与分辨率 → 拖两页 → 生成 → SDL 点选 → 拷入 SDK 上板 | 专项主闭环 |
| S2 | 迭代：改布局再生成，业务回调仍在 | 降低返工恐惧 |
| S3 | FAE：用 Hello 模板给客户演示「可视 UI + 本平台」 | 方案转化 |
| S4 | （V1）量产换皮：只下发 UI 包更新界面 | 运维效率 |
| S5 | （V2）用 MCP/AI 改工程 JSON 辅助出页 | 效率增强，非卖点前提 |

### 3.4 用户旅程（MVP）

```text
安装工具 → 新建工程（选平台）→ 拖拽控件/多页
    → 配切页与 Call function → 生成 C
    → PC SDL 预览确认 → 一键/文档接入 SDK
    → 板端显示首屏 → 在 custom/ 补业务
```

## 4. 问题与价值主张

### 4.1 要解决的问题

| 问题 | 用户痛点 | 产品回答 |
|------|----------|----------|
| P1 | 手写 LVGL 慢、易错 | 拖拽 + 生成标准 C |
| P2 | 通用工具与本 SDK 脱节 | 平台选项 + 模板 + 一键拷贝/文档 |
| P3 | 再生成冲掉业务代码 | 强制 generated / user 隔离 |
| P4 | 画布看起来像、板上不像 | 以真 LVGL（SDL）为验收，不靠 DOM 冒充 |
| P5 | 改界面就要整包重编（部分客户） | V1 起 **默认启用** A2 换包（非应用商店；可关闭） |

### 4.2 价值主张（对外可讲的三句话）

1. **为 qm10x 而生**：不是通用玩具编辑器，而是进我们 SDK 的最短路径。  
2. **真 LVGL 闭环**：生成的是标准 C，PC 与板端同一图形栈思路验证。  
3. **格式与许可自控**：自有工程，无第三方订阅墙；动态更新按需启用且边界清晰。  

### 4.3 成功指标（产品级）

| 指标 | MVP 目标（建议） | 说明 |
|------|------------------|------|
| 主闭环可演示 | KF-01～08 全部可演示 | 立项门禁 |
| Hello 上板 | ≥1 款 qm10x\* 按文档显示首屏 | AC-005 |
| 再生成安全 | user 区业务不丢失 | AC-002 |
| FAE 路径 | 上板文档 ≤10 步跑通 Hello | 需求 NFR |
| （V1）换包 | 默认启用 A2；不重编业务 C 可改界面 | AC-010 |
| 架构健康 | 后置能力 AR 评审通过 | 防推倒重来 |

量化人天/转化率等经营指标由项目在计划中补充。

## 5. 产品范围与优先级

### 5.1 必须有（Must）— 对应立项必达

| 能力 | 用户可感知结果 |
|------|----------------|
| 可视化拖拽 + 多页 | 不用手写 JSON 也能出界面 |
| **画布工作台**（标尺、设备框+网格、缩放+视图、指针坐标、底栏日志/资源/配置） | 对标 Beken/UIBuilder 基本观感；**无滚动条**；滚轮缩放、左键拖空白区平移；事件编辑仍在右栏 |
| 属性检查器（几何、文本、图片路径、**样式背景图资源选择**等） | 右栏改属性即改工程 JSON；图片字段走资源管理，对齐 Beken |
| 图形化事件（切页、Call function） | 可交互的多页 demo |
| 生成标准 LVGL C + 用户区隔离 | 可编译、可迭代 |
| SDL 真预览 | PC 上可点选验证 |
| qm10x\* SDK 接入 | 板端看得到首屏 |
| 自有 JSON 工程 | 可版本管理、可私有化演进 |

### 5.2 应该有（Should）— V1

| 能力 | 说明 |
|------|------|
| 样式 Part/State、字体裁剪 | 接近量产 UI 质量；V1 对齐 Beken 38 控件属性规格 |
| 38 控件属性 + extraData 编辑器 | 列表/表格/图表等内嵌编辑，非子控件树 |
| 三平台模板补齐 | qm10xd/v/h |
| CLI 无头生成 | 便于 CI / 脚本 |
| **默认启用** A2 UI 包 + 薄 Loader | 量产换皮（可改 `static_c` 关闭） |

### 5.3 可以有（Could）— V2+

| 能力 | 说明 |
|------|------|
| 编辑器内 Wasm 真预览、热替换 | 体验升级 |
| MCP / AI 改工程 | 效率工具 |
| 逻辑图、动画、i18n | 复杂 HMI |
| Figma 导入、Online、UI 截图测试 | 工程化上限 |

### 5.4 不会有（Won't）— 本产品线

| 不做 | 原因 |
|------|------|
| 他厂工程一键兼容 | 成本高、法律与维护风险 |
| 完整应用宿主 / 应用商店 | 另一产品线（范式 B） |
| 测控仪器台 / EEZ Flow 全家桶 | 偏离专项 |
| 闭源他厂 runtime 换皮 | 合规红线 |

### 5.5 交付与设计双轨（对研发的产品要求）

- **交付：** Could 类可后置，不阻断 MVP 发布。  
- **设计：** MCP、A2、Figma、Wasm 等须在 MVP 架构中预留扩展点（见需求文档 AR），避免「下期再做」变成「架构重做」。

## 6. 产品形态与体验原则

### 6.1 形态

| 项 | MVP | 演进 |
|----|-----|------|
| 客户端 | 桌面应用（可先 Windows） | Win / macOS / Linux |
| 自动化 | CLI：validate / generate / preview | CI、UI 测试 |
| 板上 | A1：C 编入固件 | A2：薄 Loader + UI 包 |

### 6.2 体验原则

1. **闭环优先于控件数量**：先保证「拖拽 → 可运行」，再扩控件库。  
2. **像素以真 LVGL 为准**：设计器画布可近似，验收看 SDL/板端。  
3. **画布工作台是基本盘**：标尺/网格/缩放/坐标/底栏辅助 Tab、**Delete 删除**、**画布右键菜单** 为 P0，不是「后期抛光」。  
4. **业务代码神圣不可侵犯**：生成策略必须保护 `forgeui_generated/custom/`。  
5. **平台路径要短**：从工具到 qm10x SDK 的步骤可教、可抄、可一键。  
6. **诚实表述动态更新**：是「换 UI 包」，不是「安装 App / 应用商店」。  

### 6.3 品牌与合规口径

- 不宣称兼容某某官方工程或官方 XML Engine。  
- 不使用他厂商标素材冒充联合品牌（除非有授权）。  
- 开源组件遵守许可；禁止 GPL 换皮闭源。

## 8. 竞品对照下的产品选择（摘要）

| 维度 | 行业常见做法 | 本产品选择 |
|------|--------------|------------|
| 范式 | A 导出 C / B 应用包 | **A 为主 + A2 薄包默认启用** |
| 预览 | Play / Wasm / SDL | **MVP = SDL**；Wasm 后置 |
| 绑定 | 中立或绑芯片 | **绑 qm10x\*** |
| 格式 | 专有 / XML / JSON | **自有 JSON** |
| 动态更新 | 无 / 厚宿主 OTA | **可选自有 UI 包** |
| 工程化 | Figma/CI/MCP | **后置交付，设计预留** |

详细对比见竞品报告；需求级映射见设计需求文档 §3。
