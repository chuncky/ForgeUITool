# 嵌入式 UI 可视化设计工具立项书

> **文档类型：** 项目立项书（含可行性结论）  
> **项目名称：** qm10x 系列平台 LVGL 可视化 UI 设计工具（产品暂名：ForgeUI Kit，可替换）  
> **专项目标：** PC 端拖拽式开发，拖拽即可生成可编译、可上板的 LVGL UI  
> **版本：** V1.3  
> **日期：** 2026-08-03  
> **V1.3：** 体验对标补充：画布工作台（标尺/网格/缩放/坐标/底栏辅助 Tab）为 MVP 基本要求（需求 V2.18）。  
> **V1.2：** 体验对标补充：样式背景图须可从资源库选择（与 Beken 一致；需求 FR-016c）。  
> **V1.1：** 补充 **控件属性面板**为体验对标项（Beken 38 控件 + Part/State）；用户手册 `docs/工具详细说明手册/控件属性面板使用说明.md`。  
> **状态：** 草案（待评审签字）

## 1. 立项摘要

| 项 | 内容 |
|----|------|
| 建设内容 | 面向 **qm10xd / qm10xv / qm10xh** 的 LVGL 可视化设计工具：自有 JSON 工程 → 拖拽设计 → 生成标准 LVGL C → PC 真 LVGL 预览 → 接入平台 SDK；一期起可选 UI 包动态更新 |
| 建设必要性 | 补齐平台方案「UI 开发效率」短板；降低对手写 LVGL 布局的依赖；形成可随 SDK 交付的差异化工具链能力 |

| 建议结论 | **建议立项**。MVP 聚焦必达闭环（含画布工作台基本 chrome）；后置能力（MCP/Figma/Wasm 等）交付可分期，**架构须同期预留** |
| 关联文档 | 竞品对比、产品定义书、设计需求文档（见 §9） |

## 2. 背景与问题

### 2.1 业务背景

qm10x 系列平台面向带屏嵌入式产品。客户与内部方案在 UI 开发上普遍存在：

1. **手写 LVGL 成本高**：布局、多页、样式、资源路径易错，迭代慢。  
2. **通用第三方工具不适配**：SquareLine / LVGL Pro / EEZ 等或订阅/授权约束，或与本平台 SDK/工程结构脱节，上板路径长。  
3. **芯片厂工具绑定他厂 SoC**：UIBuilder、Beken Designer 等强绑各自芯片，无法直接作为 qm10x 方案标配。  
4. **量产改界面诉求**：部分场景希望少改业务固件即可换皮/换布局，需要受控的动态更新能力（非完整应用商店）。

### 2.2 专项目标（输入）

> 做 UI 的 PC 拖拽式开发工具，使「拖拽即可生成可编译 UI 程序」。

本立项将其收敛为：**在 qm10x 平台 SDK 语境下可验收的产品**，而非「厂商中立、任意芯片」通用工具。

### 2.3 若不立项的风险

| 风险 | 说明 |
|------|------|
| 方案竞争力不足 | 同业已标配可视化 UI 工具，仅靠手写 LVGL 拉长导入周期 |
| 依赖外部工具不可控 | 订阅、控件限额、工程格式变更、与 SDK 集成靠客户自行摸索 |
| 知识沉淀分散 | 各项目各写一套 UI，无统一工程格式与生成约定 |

## 3. 建设目标

### 3.1 总目标

交付一套 **自有许可、自有工程格式** 的 PC 端 LVGL UI 设计工具，作为 qm10xd / qm10xv / qm10xh 平台软件工具链的组成部分，支撑「设计 → 生成 → PC 验证 → SDK/板端运行」闭环。

### 3.2 分期目标

| 阶段 | 目标（摘要） | 成功判据（摘要） |
|------|--------------|------------------|
| **MVP（必达）** | 拖拽多页、事件、生成 C、SDL 真预览、接入至少一款 qm10x\* SDK；**画布工作台基本 chrome** | 需求文档 KF-01～08、AC-001～007；FR-021a～d、FR-010g |
| **V1（一期）** | 样式加深、字体、平台模板补齐、CLI；可选 A2 UI 包 + 薄 Loader | 换包不重编业务 C（若启用 A2） |
| **V2+（差异化）** | Wasm/MCP/逻辑图/动画/i18n 等 | 按产品定义与需求分期，不阻断 MVP 立项 |

### 3.3 明确不做（立项边界）

- 兼容打开 SquareLine / LVGL Pro / EEZ / 他厂专有工程格式  
- 复用他厂闭源预览器、导出器、官方 XML Engine、专有 GUI 宿主  
- 完整范式 B（多 App、厚宿主、应用商店）  
- EEZ 级测控仪器台 / Flow 全家桶作为本专项范围  
- 将 GPL 工具换皮为闭源商业产品而不履行许可义务

## 4. 可行性分析

### 4.1 技术可行性 — **可行**

| 维度 | 结论 | 依据 |
|------|------|------|
| 范式选型 | 范式 A 已被多家验证；工程量可控 | 竞品报告：SquareLine / Beken / UIBuilder / EEZ / Pro |
| 预览 | MVP 用「生成 → 编译 → SDL+LVGL」，与上板同源 | Beken / UIBuilder 路径可复制；Wasm 后置 |
| 格式 | 自有明文 JSON + Schema，Git 友好 | Beken / EEZ 实践；避免 L4/L5 |
| 平台绑定 | SDK 拷贝 / 模板 / 文档为集成层，核心生成器可模块化 | 对标 UIBuilder「一键进 SDK」能力，对象改为 qm10x\* |
| 动态更新 | A2 为薄 Loader，非重做 OS | 需求文档 A-hybrid；与范式 B 隔离 |
| 合规 | 不兼容他厂二进制；开源依赖选用宽松许可组件；自研核心 | 需求 OUT / NFR |

**建设顺序（已验证共识）：** Schema → CodeGen → 真预览（先 SDL）→ 设计器 →（可选）Wasm / 逻辑图 / MCP。

### 4.2 经济与资源可行性 — **待填数后确认**

| 项 | 建议写法（评审时填实） |
|----|------------------------|
| 人力 | 建议：设计器 1～2、代码生成/预览 1～2、平台 SDK 集成 1、测试/文档 0.5～1；合计约 **4～6 人** 量级（可按编制调整） |
| 周期 | MVP 建议 **3～6 个月**（视是否已有 Schema/生成器雏形）；V1 含 A2 再 **+2～4 个月** |
| 软硬件 | 开发机；qm10xd/v/h 评估板；目标平台 SDK 与工具链；可选 CI 机 |
| 外购 | 原则上不采购第三方 UI IDE 授权作为核心；字体工具等可按需 |

> 本稿不编造预算数字；过会前由项目经理补齐 **人月、费用、里程碑日期**。

### 4.3 市场与竞争可行性 — **可行（平台绑定策略）**

| 路径 | 说明 |
|------|------|
| 不与 SquareLine/Pro 正面拼「中立生态」 | 本产品卖点是 **qm10x SDK 最短上板路径 + 许可自控** |
| 不照搬 Persim/FlyThings | 避免厚宿主；动态更新用 A2 薄方案满足部分诉求 |
| 可吸收 Beken/EEZ 实现经验 | 明文工程、用户区隔离、SDL/Wasm 思路；禁止 GPL 换皮 |

详见《嵌入式UI工具_竞品对比分析报告.md》。

### 4.4 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 先做花哨 IDE、生成物不可用 | 高 | MVP 门禁：CLI 无设计器也可 validate+generate+preview |
| 范围膨胀至范式 B / 仪器台 | 高 | 立项边界 + 需求 OUT；另立产品线 |
| A1/A2 语义分叉 | 中 | 共用语义表；架构预留 AR 设计期必审 |
| LVGL 大版本跟随 | 中 | 产品 MVP 仅承诺 **1 条版本线：LVGL 9.10**（见概要设计 D-04） |
| 平台 SDK 接口变动 | 中 | 集成层插件化；模板按平台分期 |
| 后置功能未预留导致推倒重来 | 中 | 交付分期 ≠ 设计分期；AR + 架构评审门禁 |

## 5. 建设内容与范围

### 5.1 必达范围（不过会不立项）

对应需求文档 **KF-01～08**，以及画布工作台 **FR-021a～d、FR-010g（P0）**：

1. 可视化拖拽设计  
2. 多屏 / 页面管理  
3. 图形化事件 / 动作（含 Call function → 用户区）  
4. 用户代码隔离（单目录 `forgeui_generated/` + 内嵌 `custom/`）  
5. 标准 LVGL C 导出  
6. PC 真 LVGL 预览（SDL）  
7. qm10x\* 平台工程与 SDK 接入  
8. 自有明文 JSON 工程格式  
9. **画布工作台基本要求**（标尺+屏区高亮、设备框+舞台网格、缩放+视图菜单、指针坐标、底栏日志/资源/配置；事件仍在右栏）— 需求 FR-021a～d、FR-010g  

### 5.2 一期及以后（立项认可方向，不作为 MVP 阻断）

- V1：Part/State、**38 控件属性面板**（对标 Beken `component-specs`，含样式背景图资源选择）、字体裁剪、多平台模板、CLI、可选 A2  
- V2+：Wasm、MCP、逻辑图、动画、i18n、Figma 等  
- 上述能力在 MVP **方案设计阶段必须做架构预留（AR）**，详见需求文档 §3.6 / §8.2  

### 5.3 交付物

| 交付物 | 说明 |
|--------|------|
| 设计器安装包 / 可执行程序 | MVP 可先 Windows |
| 工程格式与 Schema 说明 | 自有 JSON |
| 代码生成器与 CLI | validate / generate / preview |
| SDL 仿真工程模板 | 与生成物配套 |
| qm10x\* 接入文档与模板 | 至少一款平台跑通上板 |
| （V1）UI 包格式 + Loader 参考实现 | 若启用 A2 |
| 需求 / 设计 / 测试文档 | 与研发流程同步 |

## 7. 投资与效益（定性）

### 7.1 预期效益

1. **缩短 UI 导入与改版周期**（拖拽 + 生成 + 预览 vs 纯手写）。  
2. **强化 qm10x 方案完整性**（工具链与芯片/SDK 一体叙事）。  
3. **许可与格式自控**，避免订阅墙与他厂格式锁定。  
4. **为量产换皮预留 A2 能力**（一期），而不背负范式 B 级成本。  

### 7.2 成本构成（类别）

人力研发、评估板与工装、CI/构建环境、文档与培训、后续维护（LVGL 版本跟进）。
