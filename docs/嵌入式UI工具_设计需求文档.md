## 2. 产品定位与范围

### 2.1 一句话定位

> 面向 **qm10xd、qm10xv、qm10xh** 等平台的 LVGL 可视化设计工具：编辑自有 JSON 工程 → 拖拽设计 → **主路径生成标准 LVGL C** → PC 真 LVGL 可点选 → **文档化 / 一键接入对应平台 SDK**；可选 **导出可装载 UI 包** 支持界面（及受限逻辑）动态更新。格式与许可自控。

**目标平台（首期）：** qm10xd、qm10xv、qm10xh（后续同系列可扩展，以工程内平台选项为准）。  
**非目标：** 不做「任意芯片通用、厂商中立」定位；模板、SDK 路径、上板文档以上述平台为主。

### 2.2 设计决策（锁定）

| 决策项 | 选择 |
|--------|------|
| 目标平台 | **qm10xd / qm10xv / qm10xh**（及同系列扩展） |
| 产品范式 | **范式 A（LVGL 源码导出）** 为主 |
| 动态更新 | **A-hybrid 双交付**：A1 静态 C + A2 自有 UI 包 + 板端薄 Loader（**不是**范式 B） |
| 板上图形栈 | 开源 **LVGL** + 目标平台 port；（A2）加自研薄 Loader |
| SDK 接入 | 对接 **目标平台 SDK**（路径可配、支持一键拷贝 `forgeui_generated/`) |
| 兼容策略 | 功能与体验对齐行业主流（L1+L2）；**不**做他厂官方工程格式兼容（L4）、**不**复用他厂闭源运行时/导出器（L5） |
| 工程格式 | **自有明文 JSON** |
| 预览 MVP | 生成后本机 **SDL + LVGL** |
| 预览演进 | 可插拔；目标体验接近编辑器内真 LVGL 预览 |

### 2.3 术语

| 术语 | 定义 | 禁止混用为 |
|------|------|------------|
| **A1 静态交付** | Schema → CodeGen → LVGL C → 编入固件 | — |
| **A2 动态交付** | Schema → 自有 UI 包 → 板上 Loader 装载/替换 | 范式 B、应用商店 |
| **应用侧动态更新（A 内）** | UI 包内可更新动作表/绑定/可选受限逻辑模块；驱动与安全仍在固件 | 完整应用宿主、多 App |
| **范式 B** | 厚宿主 + 可安装完整应用（另产品线） | 与 A2 混称 |

### 2.4 能力取舍（摘要）

取舍结论见 **§3**；此处仅记边界：吸收七家「设计器骨架 + A 类交付」能力，**不做**厚宿主 / 智能屏 so 闭环 / 仪器台全家桶；格式与预览引擎自研，不兼容他厂工程。

### 2.5 范围边界

| 纳入 | 不纳入 |
|------|--------|
| 面向 **qm10xd / qm10xv / qm10xh** 的设计器、Schema、A1 CodeGen、SDL 预览、**平台 SDK 接入** | 他厂工程格式一键兼容；**通用任意芯片中立定位** |
| A1+A2 双交付；自研 Loader；受限应用侧动态更新 | 完整范式 B（多 App、厚宿主、应用商店） |
| 可选 Wasm 预览、MCP、事件图 | SCPI 仪器台、测控 IDE 全家桶 |
| 标准 LVGL C 导出（进目标平台工程）；可选后期 MicroPython | 复用他厂闭源 Play/Wasm/XML Engine |

> **用途：** 项目立项 / 范围评审的主读章节。能力维度对齐 `嵌入式UI工具_竞品对比分析报告.md` **§4.1 能力矩阵** 与 **§10 总结论**。

### 3.4 拉开差距项（竞品 §10）在本产品的落点

| 差距维度（竞品结论） | 本产品选择 |
|----------------------|------------|

### 3.5 与详细需求、分期的关系

```
§3 KF / 分层  ──指导──►  §9 分期（MVP/V1/V2）──交付──► FR 实现
        │
        ├──映射──►  §5 FR 细则  ──功能验收──►  §10 AC
        │
        └──预留──►  §3.6 / §8.2 AR  ──架构评审──►  AC-AR-*（设计期门禁）
```

- 变更 **必达** 集合 → 必须升版并重评立项。  
- 在 **差异化** 内加减项 → 可走常规需求变更，不自动改变立项结论；**若砍掉某后置能力，须同步废止或改写对应 AR**。  
- **不做** 项若要纳入 → 须另立产品线或升版重评（尤其范式 B / 仪器台）。  
- **交付可后置 ≠ 设计可后置**：一期/差异化功能在 MVP 方案中必须有 AR 落点（接口、数据模型、模块边界），允许实现为空壳/桩，禁止架构写死导致后期只能推倒重来。

## 8. 架构约束（需求级）

### 8.1 主数据流（锁定）

```text
设计器 / CLI /（未来 MCP·Importer）
              │
              ▼
        自有 JSON（唯一权威）── 校验（Schema）
              │
     ┌────────┼────────────────┐
     ▼        ▼                ▼
  设计器视图  A1 CodeGen     A2 Packer（可后置实现）
              │                │
              ▼                ▼
         forgeui_generated/   自有 UI 包（含 custom/）
              │                │
              │                ▼
              │           自研薄 Loader
              └──────────► 开源 LVGL
                    ▲
                    │
            预览后端（SDL / 未来 Wasm）
```

| ID | 约束 |
|----|------|
| C-001 | 设计器与 CLI 不得维护两套不一致的生成逻辑；未来 MCP/Importer 亦须走同一工程模型 |
| C-002 | DOM 近似不得作为像素验收标准 |
| C-003 | 若做 Wasm 预览，须自研且与 `lvglVersion` 绑定 |
| C-004 | A2 Loader、MCP、Figma、逻辑图可关闭；**平台 SDK 拷贝**为 qm10x* 主路径能力，可按平台开关 |
| C-005 | A2 不得演进为厚宿主；要做多 App/商店须另立范式 B 需求 |
| C-006 | A1 与 A2 共用控件语义表 |
| C-007 | **交付分期不得省略架构预留**：§8.2 全部 AR 须在 MVP《软件设计说明》中有模块/接口落点，否则不得宣布架构冻结 |

### 8.2 架构预留（AR）— 设计期 P0

> **性质：** 约束方案与代码边界，**不**要求 MVP 交付完整用户功能。  
> **通过标准：** 设计评审能指出「扩展点在哪、数据怎么流、禁止怎么写」；允许空实现。  
> **失败标准：** 后置功能只能靠推翻 Schema / 生成器 / 工程模型才能补上。

#### 8.2.1 工程模型与工具链总线（MCP / CLI / Online 共用）

| ID | 预留要求 | 阻塞的后置能力 | 设计期验收 |
|----|----------|----------------|------------|
| AR-020 | 存在稳定的 **工程模型 API**（打开/读写/校验/保存），GUI 仅为调用方之一 | MCP、Online、无头 CI | 设计说明有 API 列表；设计器改属性最终调用该 API，而非直写散落文件 |
| AR-021 | `validate` 与「模型变更 → 校验 →（可选）刷新视图」管道可被非 GUI 触发 | MCP、CLI | CLI 已用同一校验器；文档写明 MCP 将复用 |
| AR-022 | MCP/AI **只允许**改自有 JSON 模型，禁止直接改 `<codegenDir>/`（非 custom）或他厂格式 | MCP（FR-072） | 设计说明写清权限边界；生成仅经 CodeGen |

#### 8.2.2 A1 / A2 双交付（UI 动态更新）

| ID | 预留要求 | 阻塞的后置能力 | 设计期验收 |
|----|----------|----------------|------------|
| AR-010 | 控件 **语义表 / IR** 与「C 生成」「UI 包装载」解耦；禁止只为 `printf` 式 C 模板硬编码、无法再派生包格式 | A2（FR-080～085） | 设计说明展示：同一屏对象树 → CodeGen 与 Pack 两条后端 |
| AR-011 | 工程含 `deliveryMode`（或等价）；Schema 预留 pack 所需字段扩展点（`schemaVersion`） | A2 | DR-005 已含；扩展策略写明 |
| AR-012 | **Packer**、**Loader** 为独立模块边界（可先 stub）；不得把「仅静态 C」写死进核心类型名/目录契约以至于无法加包 | A2 | 模块图含 Packer/Loader；MVP 可 NotImplemented |
| AR-013 | A2 成功判据绑定「薄 Loader + LVGL」，禁止方案滑向厚宿主/多 App | A2 / 防范式 B | 对照 C-005、OUT-004 |
| AR-014 | 事件/动作与「固件 Call 符号表」分层建模，便于日后「动作表随包、Call 留固件」 | FR-090～092 | 数据模型有 action 与 host-call 分界 |

#### 8.2.3 Figma / 外部设计导入

| ID | 预留要求 | 阻塞的后置能力 | 设计期验收 |
|----|----------|----------------|------------|
| AR-030 | 导入链路形态固定为 **外部文件 → Adapter → 自有 JSON**；Figma 只是 Adapter 之一 | Figma（FR-073） | 设计说明预留 `importers/`（或等价）插件位 |
| AR-031 | 禁止出现第二种权威工程格式；导入失败不得污染半份 `forgeui_generated/` | Figma、其他导入 | 权威仍是 JSON；导入为事务性写入模型 |

#### 8.2.4 可插拔预览与逻辑视图

|----|----------|----------------|------------|
